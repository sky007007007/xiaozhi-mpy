# 05 · 路线图与 Git 自动化烧录

## 目标

1. 制作自己的 ESP32-S3（N16R8）MicroPython 小智固件；
2. 仓库即资料库 + 构建源；
3. Git 流程驱动烧录，目标是"小程"设备一键/自动刷机。

## 路线图

### 阶段 0 · 资料整理（当前，已完成）

- ✅ 逆向报告、布局、格式差异、51 模块 + 反汇编入库

### 阶段 1 · 源码还原

- 反汇编 `xiaozhi.py` `client.py` `ovoui.py` `ovomini.py` `user.py` `onboarding.py` `wifinet.py` 等定制模块，
  人工还原为可读 .py 源码（`src/` 目录）；
- 原生 C 模块 `xiaozhi_native` 从机器码分析接口签名（AGC/音频路径等）。

### 阶段 2 · 自建固件

- 用官方 MicroPython 1.30-preview（ESP-IDF 5.5.x）自编译 esp32 S3 固件；
- 冻结 `src/` 模块 + 标准库集合（清单见 docs/04）；
- 处理 ESP-SR 唤醒词分区（0x290000 wn9_nihaoxiaozhi_tts）与音频驱动（I2S + AFE）。

### 阶段 3 · 自动化烧录（git 驱动）

**方案：CI 构建产物 + 本地烧录脚本**

```
git push → CI（构建 .mpy 冻结包 / 整包固件，产出 Release 附件）
        → 本地 pull / 下载 Release
        → tools/flash.py 烧录到小程机
```

- `tools/flash.py`：esptool 封装，支持 `--port` 自动探测；
- 后续可选进阶：本地常驻 watcher 监听仓库新 Release 自动刷机；
  或 Gitee Go / GitHub Actions self-hosted runner 直接在局域网机器上执行烧录。

## 约定

- 原版 bin 仅作参考基线，改名不改内容；
- `extracted/` 与 `disasm/` 是逆向产物（只读基线），还原的源码放 `src/`；
- 每次成功烧录在 Release/commit message 里记录板卡与结果。
